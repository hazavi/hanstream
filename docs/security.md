# Security controls

The backend accepts read-only API calls from the configured frontend origins. CORS compares complete origins, never suffixes or wildcards. Lookup lengths, page ranges, dates, duplicate query parameters, control characters, and drama/episode routes are validated before source reads begin. CORS is a browser restriction, not authentication; the public catalog endpoints remain publicly reachable.

Server HTML readers request only configured HTTPS origins. Redirects are checked at each hop and are never followed automatically. Requests share a cache, with at most 24 uncached HTML reads outstanding. Failed hosts cool down for one minute. Responses larger than 5 MB are canceled while streaming, and rejected responses release their bodies. These bounds limit resource use inside one backend process; they are not a distributed rate limiter or DDoS service.

The backend sends Content-Security-Policy, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy, and production HSTS headers. Camera, microphone, location, payment, and USB permissions are disabled. Production scripts cannot use eval. The regular Next server uses a per-request nonce for approved bootstrap and framework scripts, with HTML caching disabled to prevent nonce reuse.

For GitHub Pages, the build calculates SHA-256 hashes for the exact inline boot scripts in every HTML document. Its CSP allows those hashes and same-origin script files, without unsafe-inline or unsafe-eval for scripts. Network connections are restricted to the site and its configured backend. The artifact check fails when a boot-script hash is missing or private configuration is included. Pages cannot supply this app's custom response headers: the meta policy does not provide frame-ancestors, HSTS, Permissions-Policy, or X-Content-Type-Options. A host or proxy that supports custom headers is needed to add those controls to the static frontend. See [MDN's CSP documentation](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy) and [Next's CSP guide](https://nextjs.org/docs/app/guides/content-security-policy).

Playback and trailer frames use a sandbox that permits scripts, origin storage, and presentation while blocking popups, downloads, forms, and top-level navigation. Player URLs must use HTTPS hostnames without credentials, literal IPs, or local hostnames. The source domains are independently operated; sandboxing does not verify their content or availability. Trailers send the site origin as a referrer for player identification. Personal library data stays in browser storage.

Run `npm audit --omit=dev` to check production dependencies and `npm audit` for the whole toolchain. Both currently report zero findings after compatible dependency fixes. See [security operations](security-operations.md) for CI checks, shared rate-limit integration, proxy trust, protected diagnostics, DNS restrictions, and credential rotation. This review and its regression tests are not a penetration test or a guarantee against all attacks.
