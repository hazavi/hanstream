# Player protection

The Windows player uses a separate unprivileged WebView2 surface. It installs HTTP(S) request interception before navigating to the player, then blocks known advertising hostnames, literal IP addresses, and local hostnames. Matching uses a process-wide hostname set and label-boundary suffix checks. Configured player origins are exempt from hostname filtering so a list entry cannot block the selected player itself.

Popups, new windows, downloads, device permissions, and script dialogs are blocked. A fixed local document-start script also prevents popup/close/print calls and new-tab anchor navigation. Navigation is limited to approved HTTPS origins and the selected player's path. Browser security and SmartScreen remain enabled. Player pages never receive library permissions.

The browser player blocks popups, new tabs, downloads, and top-level navigation through its iframe sandbox. No extension or ad-filter download is required. Fullscreen uses the iframe's permissions attribute without a duplicate legacy attribute. Delay and server notices use short-lived, dismissible toasts.

A webpage cannot inspect another origin's player DOM or filter its internal network requests. Browser extensions may still report blocked advertising requests in developer tools; those messages do not mean the app's popup blocker failed. The sandbox does not grant third-party storage access to silence provider warnings. Deleted uploads and provider challenges cannot be repaired by disabling browser protection.

The source reader checks only configured `PLAYER_ORIGINS` (or `DESKTOP_MEDIA_ORIGINS`) for explicit removal pages. Checks have a 1.5-second budget, public-address DNS checks, a 256 KB HTML limit, and at most four active requests. Redirects, denied requests, timeouts, and challenges are not treated as proof of deletion. A removed upload is skipped in favor of another listed server; if all uploads were removed, the source page is refreshed once to look for replacements. No arbitrary player-URL proxy is exposed. The old optional extension build script remains a developer tool and is not included in the website build or advertised in its player.

Rules are an offline derived subset of EasyList's unconditional ad-server hostnames. Conditional, path, and cosmetic rules are not treated as unconditional blocks. Attribution, the pinned revision, hashes, and the CC BY-SA 3.0 license are in `resources/network-blocklist.NOTICE.md` and `resources/network-blocklist.LICENSE.txt`. The installer and extension include the notices. Keep the adjacent `licenses` folder when distributing the portable executable. Builds never fetch new rules; updates require an explicit immutable upstream revision and review.

Set reader-only `PLAYER_PREFERRED_ORIGINS` to tested embed-compatible player origins, in preference order. Other listed players remain available as backups. The player starts each episode with the reader's current preferred URL; obsolete saved server indices no longer override it after the source changes its server list. A provider's preview image or loaded document alone is not proof that the video plays.
